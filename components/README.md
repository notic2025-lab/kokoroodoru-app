## 使い方

1. 公開ページで部品を検索し、昼／夜と一覧／スマホ幅を切り替える。
2. 各カードの「HTML ↗」で見本のHTMLをコピーする。
3. `components.css` と `extended.css`（AR部品は `ar.css` と `ar-world.css` も）を読み込んだ画面へ配置する。
4. アプリ側の状態・データ・操作処理を接続する。

コピーは見本のマークアップです。デモの `data-*` 属性は除き、フォームIDと参照、ラジオボタン名を重複しにくい名前へ変更します。入力値、チェック状態、選択肢も反映します。AR部品は接地と重なりを保つため、表示面のラッパーも含めてコピーします。イベント処理やダイアログ本体までを自動で移植する機能ではありません。アプリへ複数部品を統合する際は、ID・名前と状態の管理を確認してください。

## ファイル

- `index.html`: 全92部品の静的HTML。JavaScriptなしでも部品を閲覧可能。
- `components.css`: 配色変数、書体、基本部品、部品集レイアウト。
- `extended.css`: 追加部品とレスポンシブ表示。
- `components.js`: 昼夜・幅、基本部品、HTMLコピー。
- `extended.js`: 部品検索、追加部品のローカル操作と確認ダイアログ。
- `ar.css` / `ar.js`: ARの20部品と表示設定。
- `ar-world.css`: 共通の光の素材と動き。
- `experience/`: 「気配をたどる」4場面の体験プロトタイプと設計意図。
- `assets/ar-park.webp`: 参考写真をもとに生成したAR用の仮の風景。
- `ar-design.md`: ARの設計意図と実装への引き継ぎ。
- `catalog.json`: 番号・名称・状態・分類・検索キーワード。

このディレクトリはビルド不要です。`python3 -m http.server 8000` をリポジトリ直下で起動し、`http://localhost:8000/components/` から確認できます。HTTPS以外ではブラウザによってクリップボードの利用が制限されます。

## 共通の指定

テーマは祖先要素の `data-theme="night"` で切り替えます。通常は昼です。`--ui-*` 変数と `ui-*` クラスが部品の共通基盤です。`sample`、`specimen`、`catalog`、`sidebar` などは部品集のレイアウト用です。既存アプリに取り込む際は必要なクラスを移し、グローバルリセットとの競合を確認してください。

Google Fontsが取得できない場合はシステムフォントにフォールバックします。画像は既存リポジトリの参照画像です。アバターの人物アイコンは配置用の仮表示で、アプリのキャラクターに置き換えます。

## 表示・操作の設計

- 選択を色だけで表現せず、チェック、ラベル、形でも示す。
- 主要操作は44px以上。写真上の補助削除ボタンはコンパクト表示の見本。
- 入力にはラベルと説明を関連付ける。
- タブは矢印・Home・Endで移動可能。非表示パネルを操作対象から外す。
- 確認にはネイティブ `dialog` を使用。Escape、フォーカス制限、閉じた後の操作元への復帰に対応。
- 削除確認の初期フォーカスはキャンセル側。
- 動きを減らす設定では、スピナーとスケルトンのアニメーションを止める。
- データは端末にも外部にも永続保存しない。

## 実装に接続する部分

ログインやOAuth復帰、端末の権限、GPS、AR、地図と経路、画像処理、投稿の保存、共有先、通知配信、問い合わせと報告、ログアウトは本番機能に接続していません。デモ操作の完了メッセージは実処理の完了を意味しません。

イベントの内容・日時、距離と時間、GPSの精度値、名前の文字数上限は見本です。GPS精度の良否判定、利用規約、保存期間、端末別の許可手順などは本番仕様に合わせてください。部品集の追加は、本番アプリの仕様やバックエンドを変更するものではありません。

元ソースを別管理しているため、再公開する際にはこの `components/` ディレクトリも公開成果物へ含めてください。
